# ODX Diagnostic Workbench

A browser UI built directly on top of the `odxtools` API.

```bash
pip install .[webdemo]
python3 examples/webdemo/server.py --port 8000   # binds to 127.0.0.1
```

Tabs: Overview, Service Inspector, Live Virtual ECU, **Fault Memory**,
Decoder and Compare (see the main [README](../../README.md#web-demo-odx-diagnostic-workbench)).

## Fault Memory

Select `somersault_dtc.pdx` in the database picker. This demo PDX is
generated by [`examples/mksomersaultdtcpdx.py`](../mksomersaultdtcpdx.py)
from `examples/somersaultecu.py` (which, like `somersault.pdx`, stays
unchanged) and adds to `somersault_base_variant`, so that both ECU
variants inherit it:

- a `DTC-DOP` (3 byte trouble code) with the DTCs `0x010001` "Acrobat
  overheated", `0x010002` "Flip aborted – too dizzy" and `0x010003`
  "Fire ring malfunction",
- a structure for the ISO 14229 `statusOfDTC` bits and a snapshot
  structure (temperature, dizziness, total flips, seconds since connect),
- the services `read_dtc_by_status_mask` (`19 02 <mask>` →
  `59 02 <availMask> {DTC status}*`, an `END-OF-PDU-FIELD`),
  `read_dtc_snapshot` (`19 04 <DTC> 01`) and `clear_dtcs`
  (`14 FF FF FF` → `54`).

Regenerate it with `python3 -m examples.mksomersaultdtcpdx`.

The tab shows a session timeline with a marker for every stored or
updated DTC, one card per DTC returned by `19 02` (hex code, ODX text,
occurrence counter and the eight status bits), a snapshot drawer
(`19 04`) and the request/response byte strips of every exchange. A
"Provoke fault" menu drives the ECU into each fault. All requests are
sent through the live session, so they also appear in the CAN trace
and the transaction log of the Live Virtual ECU tab.

**Real:** encoding and decoding of all telegrams by odxtools, including
the DTC codes and texts which come from the `DTC-DOP`; ISO-TP over
`can-isotp` on a python-can `virtual` bus; the state chart evaluation
by `odxtools.statemachine`.

**Modeled:** the fault triggers (temperature above the limit, a flip
refused for dizziness, a failed flip through the fire ring), the status
bit handling (a new fault sets `testFailed` and `pendingDTC`, a repeated
one also `confirmedDTC`; the overheat fault clears `testFailed` once the
acrobat cooled down) and the occurrence counter.
