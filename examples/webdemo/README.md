# ODX Diagnostic Workbench

A browser UI on top of the `odxtools` API.

```bash
pip install .[webdemo]
python3 examples/webdemo/server.py --port 8000   # binds to 127.0.0.1
```

Tabs: Overview, Service Inspector, Live Virtual ECU, **Fault Memory**,
Decoder and Compare (see the main [README](../../README.md#web-demo-odx-diagnostic-workbench)).

## Fault Memory

Select `somersault_dtc.pdx` in the database picker (the default stays
`somersault.pdx`, which defines no fault memory). The tab shows

- a **session timeline** with a marker for every DTC the virtual ECU
  stores or updates (hover for the trigger, e.g. "temperature 66 °C >
  65 °C limit"),
- **DTC cards** filled from the decoded `19 02 FF` response: trouble
  code, ODX text, occurrence counter and the eight ISO 14229 status bits,
- a **snapshot drawer**: clicking a card sends `19 04 <DTC> 01` and shows
  the decoded snapshot record (temperature, dizziness, flips, timestamp),
- a request/response **byte strip** for every read, snapshot and clear,
  coloured by ODX parameter,
- **Provoke fault**: overheat (13 forward flips), flip while dizzy
  (10 backward flips) and a failing fire-ring flip.

All requests go through the Live Virtual ECU session, so they also show
up in its transaction log and CAN trace.

`somersault_dtc.pdx` is a demo extension generated by
[`examples/mksomersaultdtcpdx.py`](../mksomersaultdtcpdx.py) from
`examples/somersaultecu.py`. It adds to `somersault_base_variant` (and
thus to both ECU variants) a `DTC-DOP` with

| DTC        | Text                     | Modeled trigger                                   |
|------------|--------------------------|---------------------------------------------------|
| `0x010001` | Acrobat overheated       | temperature crosses `HOT_LIMIT` (65 °C)           |
| `0x010002` | Flip aborted – too dizzy | a flip is refused because dizziness ≥ 180         |
| `0x010003` | Fire ring malfunction    | a flip through the fire ring fails (any NRC)      |

plus a DTC status structure, snapshot record `0x01` and the services
`read_dtc_by_status_mask` (`19 02`), `read_dtc_snapshot` (`19 04`) and
`clear_dtcs` (`14 FF FF FF`). Regenerate it with

```bash
python3 -m examples.mksomersaultdtcpdx examples/somersault_dtc.pdx
```

### Real vs. modeled

| REAL | MODELED |
|------|---------|
| UDS `0x19`/`0x14` telegrams over a python-can `virtual` bus with `can-isotp` | the fault triggers (temperature, dizziness, fire ring) |
| encoding and decoding by odxtools from the ODX `DTC-DOP`, status and snapshot structures; DTC codes and texts come from the PDX | the occurrence counter (from the ECU model, not part of `59 02`) |
| ECU responses encoded through the ODX response objects | snapshot values and the "acrobat recovers" step used by *Provoke fault* (resets temperature/dizziness, keeps fault memory) |
