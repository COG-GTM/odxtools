# ODX Diagnostic Workbench

A browser UI built directly on the `odxtools` API.

```bash
pip install ".[webdemo]"
python3 examples/webdemo/server.py --port 8000   # binds to 127.0.0.1
```

Tabs: Overview, Service Inspector, Live Virtual ECU, **Fault Memory**,
Decoder and Compare. The general description lives in the top-level
`README.md`. This file covers the fault memory.

## Fault Memory

The bundled `somersault.pdx` defines no DTCs. The demo-only database
`examples/somersault_dtc.pdx` adds them. It is generated by

```bash
python3 examples/mksomersaultdtcpdx.py examples/somersault_dtc.pdx   # run from the repo root
```

The generator deep-copies `examples.somersaultecu.database` and adds the
following to `somersault_base_variant`, so the lazy and assiduous
variants inherit them:

- `DTC-DOP` `somersault_dtcs` (3 bytes): `010001` Acrobat overheated,
  `010002` Flip aborted – too dizzy, `010003` Fire ring malfunction
- the `dtc_status` structure: the eight ISO 14229-1 status bits, one byte
- `snapshot_record_01`: temperature (°C), dizziness (% of the flip
  limit), total flips, seconds since connect
- services `read_dtc_by_status_mask` (`19 02 mask` → `59 02 avail {DTC status}*`,
  an `END-OF-PDU-FIELD`), `read_dtc_snapshot` (`19 04 DTC 01` →
  `59 04 DTC status 01 snapshot`) and `clear_dtcs` (`14 FF FF FF` → `54`).

`somersault.pdx`, `somersault_modified.pdx` and `somersaultecu.py` are
unchanged. When `somersault_dtc.pdx` is selected, the UI shows a
"Demo PDX extension" ribbon.

The Fault Memory tab contains:

- **Provoke fault:** drives the ECU into each trigger using ordinary ODX
  services: a fire-ring flip that fails, a flip while dizzy, or
  repeated flips until it overheats.
- **Fault timeline:** one marker per stored, passed or cleared event.
  Hover over a marker to see its trigger.
- **DTC cards:** decoded from the `59 02` response, with the eight
  status-bit chips. Click a card to send `19 04` and open the snapshot
  drawer.
- **UDS exchanges:** a byte strip for each request and response,
  coloured per ODX leaf parameter. Each strip includes the nested
  structure and `END-OF-PDU-FIELD` items.

All traffic goes through the same `/api/live/send` path as the Live ECU
tab, so it also shows up in that tab's CAN trace and transaction log.

| REAL | MODELED |
| --- | --- |
| odxtools encoding/decoding of the requests and responses, including the `DTC-DOP` (codes and texts come from the PDX) | the acrobat physics that trigger the faults (temperature > 65 °C, dizziness ≥ 180, a failed flip with the fire ring lit) |
| the ODX state chart evaluation (`odxtools.statemachine`) | the fault-memory algorithm: status bits `testFailed`/`pendingDTC`/`confirmedDTC` are set when a fault is stored, and `testFailed` is reset once the condition passes. The snapshot holds the latest occurrence. The occurrence counter and the timeline events come from the model. |
| UDS over ISO-TP (`can-isotp`) on a python-can `virtual` bus, with a passive `IsoTpStateMachine` sniffer | |

Only snapshot record `0x01` exists. The ECU answers an unknown DTC or
record with the ODX general negative response, NRC `0x31`
`RequestOutOfRange`.
